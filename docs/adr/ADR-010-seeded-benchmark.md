# ADR-010 Seeded benchmark

- Status: accepted
- Date: 2026-11-03

## Context

The numeric rule needs a benchmark that fails when deterministic checks are wrong. A single blended detection rate can pass while the arithmetic is still wrong.

## Decision

The harness is a pytest module plus `python -m evidence_eval score`. Fault ids: `unit_scale`, `arithmetic`, `wrong_input`, `sign`, `stale_revision`, `false_coverage`, `broken_hash`, `bad_span`, `outside_validity`, `missing_input`. Cases are generated by the calc package and then one injector. Deterministic faults `unit_scale`, `arithmetic`, `wrong_input`, `sign`, and `outside_validity` must score recall 1.0 on the cases in this repo. `missing_input` expects abstain and forbids a numeric result. `llm_numeric_violation` must be 0.

The dev set is a representative subset, at least two cases per fault id plus clean controls, not the 140-case illustration in the plan. Holdout is a small frozen split from the same injector. Its file hash is in `bench/holdout/SHA256.txt`. Detectors do not branch on case id. Generalization beyond these generated cases is **NOT VERIFIED**.

## Alternatives

A hosted eval service was rejected. Hand-edited expected numbers were rejected.

## Consequences

A tuned holdout that special-cases ids would be dishonest. This repo does not do that, and it also does not claim the holdout is an independent population.
